# Lecture Notes v0.2.0 사용 가이드

Lecture Notes는 Windows에서 로컬 처리 서버를 실행하고 Chrome 사이드 패널에서 강의 노트를 읽는 구조입니다. 강의 파일·전사본·노트는 로컬에 보관하며, 전사와 AI 정리가 필요할 때만 OpenAI API를 사용합니다.

## 1. 처음 설치

1. 배포 ZIP을 `문서\Lecture-Notes`처럼 계속 사용할 폴더에 모두 압축 해제합니다.
2. `SETUP.cmd`를 실행합니다.
3. Lecture Notes 설정 화면에서 OpenAI API 키와 Obsidian 보관함 경로를 저장합니다.
4. Chrome의 `chrome://extensions` → 개발자 모드 → `압축해제된 확장 프로그램을 로드합니다` → 설치 폴더의 `extension`을 선택합니다.
5. JNUclass/Canvas 강의 탭을 새로고침합니다.

`SETUP.cmd`는 Windows 로그인 자동 시작과 시작 메뉴 바로가기를 등록하고 서버도 즉시 실행합니다. 이후 평소에는 `START.cmd`를 직접 실행하지 않아도 됩니다.

## 2. 기존 설치 업데이트

1. 새 배포 ZIP을 기존 Lecture-Notes 설치 폴더 위에 덮어씁니다.
2. `UPDATE.cmd`를 실행합니다.
3. 자동으로 열린 Chrome 확장 관리 화면에서 Lecture Notes의 **새로고침**을 한 번 누릅니다.
4. 이미 열려 있던 LMS 탭이 있다면 그 탭도 새로고침합니다.

업데이트 ZIP에는 사용자 데이터 폴더인 `.local`, `library`, `Obsidian`이 들어 있지 않습니다. 프로그램 파일만 교체하도록 만들어져 있습니다.

## 3. 평소 강의 하나 처리하기

권장 흐름은 다음과 같습니다.

1. JNUclass/Canvas에서 실제 강의 페이지를 엽니다.
2. Video DownloadHelper로 해당 강의 음성 또는 영상을 다운로드합니다.
3. 다운로드 완료 시 Lecture Notes 확장이 다운로드 당시의 강의 페이지 문맥을 확인합니다.
4. 강의로 확인된 파일만 로컬 자료함으로 가져옵니다.
5. 가져온 항목을 해당 강의 페이지와 자동 연결합니다.
6. 자동 처리가 켜져 있으면 전사와 노트 작성이 이어서 진행됩니다.

정상적인 흐름에서는 `강의 연결` 버튼을 누를 필요가 없습니다. 다운로드 시 문맥을 얻지 못했거나 기존 파일을 수동으로 넣은 경우에만 수동 연결을 사용하세요.

## 4. 일반 MP3가 미분류로 들어오는 것을 막기

설정의 다운로드 관련 옵션은 서로 역할이 다릅니다.

### 강의 페이지의 DownloadHelper 다운로드 자동 가져오기

켜두는 것을 권장합니다. 다운로드가 실제 지원 강의 페이지에서 시작됐다는 확장 프로그램 문맥이 있을 때만 가져옵니다.

### 다운로드 폴더의 모든 지원 파일 자동 가져오기

기본값은 OFF이며 그대로 두는 것을 권장합니다. 이 옵션을 켜면 지정 폴더의 MP3·영상·텍스트 파일 자체를 감시하므로 일반 음악도 강의 후보가 될 수 있습니다.

### YouTube 다운로드도 자동 가져오기

기본값은 OFF입니다. YouTube에서 음악을 다운로드하는 경우가 많다면 계속 꺼두세요. YouTube 강의를 실제로 자동 수집하고 싶을 때만 켜면 됩니다.

### library/inbox

앱이 직접 소유하는 명시적 입력 폴더입니다. 여기에 넣은 지원 파일은 항상 자동 스캔합니다. 수동 배치 가져오기가 필요할 때 사용하세요.

## 5. 내 강의 화면

강의는 과목별로 묶여 표시되고 카드에 현재 상태가 나타납니다.

- 다운로드 완료 · 전사 대기
- 처리 대기
- 처리 중 · 전사 N/M 구간 완료
- 전사 완료 · 노트 작성 대기
- 완료 · 노트 준비됨
- 처리 실패 · 확인 필요

`처리 상태` 영역은 정상 완료 기록을 계속 쌓아두지 않습니다. 진행 중 작업과 실패한 작업만 보여주며, 실패한 작업은 저장된 결과부터 재시도할 수 있습니다.

검색창이 보이는 상태에서 `/` 키를 누르면 바로 검색으로 이동합니다.

## 6. 미분류와 오래된 강의 정리

v0.2.0부터 삭제보다 먼저 **보관함**을 사용합니다.

보관은 목록에서 강의를 치우지만 다음은 삭제하지 않습니다.

- 원본 강의 파일
- 전사본
- 강의노트
- Obsidian에 저장된 노트
- 강의 페이지 연결 정보

사용 방법:

- 강의 행 오른쪽 보관 버튼: 한 강의 보관
- `미분류 전체 보관`: 과거 잘못 들어온 미분류를 한 번에 정리
- `보관함`: 보관된 항목만 보기
- `복원`: 개별 복원
- `모두 복원`: 보관된 항목 전체 복원

따라서 과거 버전에서 일반 음악이 미분류로 많이 들어왔다면 우선 `미분류 전체 보관`을 사용하는 것이 안전합니다.

## 7. 강의 페이지 연결

다운로드 자동 가져오기로 들어온 파일은 다운로드 당시의 강의 페이지와 즉시 연결을 시도합니다.

연결 정보에는 페이지 주소와 강의 식별에 필요한 제목/과목 정보가 들어갑니다. 브라우저 로그인 쿠키를 저장하지 않습니다.

같은 페이지를 다시 열면:

- 명시적인 연결이 하나 있으면 그 노트를 엽니다.
- 연결이 없을 때는 과목명과 강의명이 정확히 대응하는 후보가 하나뿐일 경우에만 자동으로 매칭합니다.
- 여러 후보가 있으면 임의로 하나를 고르지 않습니다.

한 강의 페이지를 다른 노트에 명시적으로 다시 연결하면 이전 자동 대상에서는 그 연결을 제거합니다. 보관된 강의도 이 중복 검사 대상에 포함됩니다.

## 8. 노트 읽기 화면

보조 기능은 `⋯` 도구 메뉴 안에 아이콘으로 정리되어 있습니다. 각 아이콘에 마우스를 올리면 기능 이름과 설명을 볼 수 있습니다.

주요 기능:

- 노트 편집
- Markdown 저장
- AI로 다시 정리
- 현재 강의 페이지 수동 연결
- 원본 폴더 열기
- 과목/강의명 정리
- 기존 노트/전사본 연결
- A4 인쇄/PDF
- 전사본 보정용 프롬프트 복사/붙여넣기
- 현재 강의 보관/복원

같은 과목의 이전/다음 강의를 상단에서 이동할 수 있습니다. 숫자가 포함된 강의명은 자연스러운 숫자 순서로 정렬합니다.

## 9. 전사본 보정

STT 오류가 눈에 띄는 강의만 전사본 화면의 보정 도구를 사용하세요.

1. `GPT 보정용 프롬프트 복사`
2. ChatGPT에서 STT 오류만 수정
3. `보정본 붙여넣기`
4. 저장

타임스탬프가 있는 전사본은 원래 구간 구조를 유지해야 합니다. 원본 전사본은 버전 폴더에 백업됩니다.

전사본을 수정해도 기존 강의노트를 즉시 덮어쓰지 않습니다. 새 전사 기준으로 노트가 필요할 때 `AI 다시 정리`를 실행하세요.

## 10. AI 품질 프리셋

기본 UI에서는 모델 문자열 대신 목적에 따라 선택합니다.

| 설정 | 실제 모델 | 추천 상황 |
| --- | --- | --- |
| 빠름 | `gpt-5.6-luna` | 비용 절약, 일반적인 내용 |
| 균형 | `gpt-5.6-terra` | 기본 추천 |
| 정밀 | `gpt-5.6-sol` | 복잡한 전공 강의·중요 시험 범위 |
| 직접 지정 | 직접 입력 | 특정 API 모델을 직접 관리할 때 |

기존 설정이 기본 `gpt-4.1-mini`였다면 v0.2.0에서 균형 프리셋으로 전환됩니다.

## 11. 긴 강의의 2단계 노트 생성

긴 전사본은 API 입력 한계와 처리 속도를 위해 여러 구간으로 나눕니다. v0.2.0에서는 구간별 결과를 그대로 붙이는 데서 끝내지 않고 기본적으로 두 번째 정리 단계를 거칩니다.

1차:
- 각 구간을 병렬로 강의노트 형태로 정리
- 앞/뒤 문맥을 일부 제공해 구간 단절 완화

2차:
- 반복된 제목 정리
- 같은 용어의 표기 통일
- 구간 경계에서 끊긴 계층 연결
- 내용 중복 최소화
- 원문 사실·수식·코드·예시·순서는 유지

추가 호출이 부담스럽다면 `긴 강의노트 최종 일관성 정리` 옵션을 끌 수 있습니다.

## 12. 시험 준비

시험 준비는 이미 저장된 노트와 전사본을 사용하며 음성을 다시 전사하지 않습니다.

범위가 짧으면 한 번에 시험 자료를 작성합니다. 범위가 길면:

1. 각 범위를 나눠 핵심 개념, 정의, 비교, 과정, 예시와 근거를 정리합니다.
2. 각 구간 결과를 파일로 보존합니다.
3. 전체 구간 결과를 다시 읽어 하나의 시험 대비 자료로 통합합니다.
4. 중복 개념은 묶고 서로 다른 조건·예시는 보존합니다.

최종 통합 호출이 실패해도 이미 작성된 구간별 정리본을 버리지 않고 하나의 결과에 남깁니다.

## 13. Obsidian 저장 구조

예시:

```text
선택한 보관함/
├─ 강의노트/
│  ├─ 운영체제/
│  │  ├─ 01 프로세스.md
│  │  ├─ 02 스레드.md
│  │  └─ 전사본/
│  │     ├─ 01 프로세스.md
│  │     └─ 02 스레드.md
│  └─ _관리/
│     └─ records/
└─ 시험대비/
```

Obsidian 플러그인은 필요하지 않습니다. Obsidian이 없어도 일반 Markdown 폴더로 사용할 수 있습니다.

패널과 Obsidian에서 같은 노트를 동시에 편집할 수 있으므로 Lecture Notes는 저장 직전에 원본이 바뀌었는지 확인합니다. 충돌이 있으면 오래된 내용으로 덮어쓰지 않고 사용자에게 알립니다.

## 14. 다른 PC에서 같은 보관함 사용

노트와 전사본 및 연결 기록은 Obsidian 보관함의 관리 레코드를 통해 이어질 수 있습니다. 단, 다음은 각 PC별 로컬 상태입니다.

- OpenAI API 키
- 로컬 서버 연결 토큰
- 작업 큐
- 절대 경로 설정

새 PC에서는 해당 PC 기준으로 `SETUP.cmd`와 Chrome 확장 등록을 다시 해야 합니다.

## 15. 서버가 안 켜질 때

평소에는 Windows 로그인 시 자동 시작합니다.

연결이 끊겼다면:

1. Windows 시작 메뉴에서 `Lecture Notes` 검색
2. 실행
3. 확장의 `다시 확인` 클릭

프로젝트 폴더를 찾아 `START.cmd`를 실행하는 것은 비상용 방법으로만 남겨두었습니다.

## 16. 권장 설정

JNUclass 강의를 중심으로 쓰는 일반적인 경우:

```text
새 파일 자동 전사·노트 작성        ON
DownloadHelper 강의 자동 가져오기  ON
다운로드 폴더 전체 감시            OFF
YouTube 다운로드 자동 가져오기     OFF
정밀 시간 정보                     OFF (필요할 때만 ON)
AI 정리 품질                       균형
긴 강의 최종 일관성 정리           ON
```

## 17. 개인 데이터와 API 비용

- API 키는 이 PC의 로컬 설정에 저장합니다.
- 배포 ZIP에는 개인 설정과 강의 자료를 넣지 않습니다.
- 전사 시 강의 음성, AI 노트/시험 자료 생성 시 해당 텍스트가 OpenAI API로 전송됩니다.
- ChatGPT 구독과 OpenAI API 사용 요금은 별도입니다.
- 브라우저 로그인 쿠키를 수집하지 않습니다.
- 출석률·재생 진도 조작 기능은 없습니다.

## 18. 업데이트 후 가장 먼저 확인할 것

v0.2.0으로 올린 직후에는 다음 네 가지만 확인하면 됩니다.

1. 확장 상단에 `v0.2.0` 표시
2. 설정의 AI 품질이 `균형` 또는 원하는 값인지 확인
3. `다운로드 폴더의 모든 지원 파일 자동 가져오기`가 OFF인지 확인
4. 테스트 강의 하나를 다운로드해 카드에 `영상 연결됨`과 처리 상태가 나타나는지 확인
